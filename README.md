# Radiance FiGS Environment Setup

Gaussian-splat capture-to-flight pipeline: a phone video of a room becomes a
metrically-aligned 3D Gaussian Splat, and a simulated drone flies a course through it
with an MPC controller rendering its onboard camera at every control step.

Built on [SousVide / FiGS](https://github.com/StanfordMSL/SousVide) (Stanford MSL).
This repository holds the install automation, the capture-to-flight pipeline script,
the configs, and the documentation — not the upstream code, and not the multi-gigabyte
artefacts either produces.

## What is here

| Path | |
|---|---|
| `setup_scripts/install_figs.sh` | Full install: miniconda, acados, tiny-cuda-nn, nerfstudio, the SousVide clone. Resumable, step-addressable. |
| `setup_scripts/verify_figs.sh` | Verification suite — imports, binaries, GPU, an end-to-end render of a shipped scene. |
| `setup_scripts/apply_overlay.sh` | Restores our configs into the freshly cloned SousVide. |
| `figs/figs_pipeline.py` | The pipeline: 14 resumable steps from raw video to validated flight render (SfM and splat training are separate steps). |
| `figs/tidy_sousvide.sh` | Keeps generated renders out of the upstream clone's root. |
| `figs/sousvide_overlay/` | Capture configs and courses that must sit inside the clone. |
| `docs/` | Flat, on purpose. `LAB_MACHINE.md` and `FiGS_pipeline_script_guide.md` are the two current ones; `FiGS_custom_video_guide.md` and `FiGS_pipeline.md` are reference. Anything mentioning `~/projects/figs_validation` is legacy for paths. The old VRAM pessimism was wrong: with `--cache-images cpu` a 4 GB card trains (see the script guide §9). |
| `runs/` | JSON run records — every measurement from every completed run. |
| `outputs/flights/` | Rendered flight videos. |

## From clone to a working pipeline

Requires an NVIDIA GPU with **at least 8 GB** of VRAM (training peaks at 5203 MiB),
CUDA 11.8-compatible drivers, ~60 GB free disk, and Ubuntu 22.04.

```bash
git clone <this repo> ~/Radiance
cd ~/Radiance

# 1. install — 1-2 hours, mostly tiny-cuda-nn. Run under tmux.
./setup_scripts/install_figs.sh --prefix ~/Radiance/figs

# 2. restore our configs into the clone install_figs.sh just made
./setup_scripts/apply_overlay.sh --checkout-pin

# 3. check it
./setup_scripts/verify_figs.sh --prefix ~/Radiance/figs --quick
```

**`--prefix` is not optional.** Both scripts default `PROJECT_ROOT` to
`~/projects/figs_validation`, which is wrong here, and without it they report a
healthy install as missing.

Then, for every session:

```bash
source ~/Radiance/figs/figs_env.sh     # NOT just `conda activate kitchen`
```

`figs_env.sh` is generated by the install (it is gitignored — it has absolute paths
baked in). It sets `ACADOS_SOURCE_DIR`, `LD_LIBRARY_PATH` and `PYTHONNOUSERSITE`;
without them a run dies ~90 minutes in on a missing `libqpOASES_e.so`, and
`LD_LIBRARY_PATH` cannot be repaired from inside a running process.

## Running a capture

```bash
source ~/Radiance/figs/figs_env.sh
~/Radiance/figs/figs_pipeline.py \
    --scene lab3 \
    --video ~/Radiance/video_captures/lab3_raw.mp4 \
    --marker-length 0.18 \
    --course lab3_loop
```

First run for a new room stops at the `course` step — waypoints live in a metric
frame you cannot know until the splat is aligned. See
`docs/FiGS_pipeline_script_guide.md` §6.

**Read `docs/FiGS_custom_video_guide.md` before filming.** Most failures in
this pipeline are filming failures, and they surface an hour later as something that
looks like a software problem.

## What is deliberately not committed

`figs/miniconda3/` (several GB, and conda is not relocatable), `figs/SousVide/`
(upstream's repo — pinned by commit in `figs/sousvide_overlay/SOUSVIDE_REF`),
`gsplats/` (~8 GB per scene, with checkpoints well over GitHub's 100 MB file limit),
and `video_captures/` (~3 GB per capture). All of it is reproducible from what is
here; see `.gitignore`, which explains each exclusion.
